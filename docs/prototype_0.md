# VisionForge Prototype 0: Video Ingestion

## Purpose
Prototype 0 provides a clean, minimal, and working pipeline to ingest an indoor `.mp4` video, sample frames at a given rate, generate a contact sheet for visual inspection, and write machine-readable metadata. This allows us to visually inspect whether a smartphone video sequence is suitable for future reconstruction.

## Architecture
The script uses `opencv-python` to read video frames. It calculates the correct frame step based on the video's original FPS and the requested sampling FPS. 
Frames are saved as JPEG images with a deterministic naming convention. 
A contact sheet is generated by resizing all extracted frames into thumbnails and placing them on a calculated grid layout.

## Dependencies
- Python 3
- `opencv-python`
- `numpy`
- `pillow`
- `pytest` (for testing)

## CLI Usage
Activate the virtual environment, then run the module:

```bash
python -m visionforge.video.extract_frames --input data/input/room.mp4 --output outputs/prototype_0 --fps 2.0
```

### Options
- `--input`: Path to the input video.
- `--output`: Path to the output directory where frames and metadata will be saved.
- `--fps`: (Optional) Target frames per second to sample (default: 2.0).
- `--max-frames`: (Optional) Maximum number of frames to extract.

## Output Structure
```
outputs/prototype_0/
├── contact_sheet.jpg
├── metadata.json
└── frames/
    ├── frame_000001.jpg
    ├── frame_000002.jpg
    └── ...
```

## Metadata Format
The `metadata.json` will contain:
```json
{
  "input": "/absolute/path/to/data/input/room.mp4",
  "duration_seconds": 12.5,
  "original_fps": 30.0,
  "frame_count": 375,
  "width": 1920,
  "height": 1080,
  "sampling_fps": 2.0,
  "extracted_frames": 25
}
```

## Frame Sampling
The sampling calculates an integer `frame_step = max(1, round(original_fps / target_fps))`. It simply reads all frames and only saves the ones matching the step interval. It does not perform sub-frame interpolation or temporal smoothing.

## Inspecting the Contact Sheet
The `contact_sheet.jpg` provides a grid of all extracted frames in chronological order with the frame number overlaid. 
By opening it, we can visually inspect the viewpoint overlap, motion blur, and coverage of the captured sequence to determine if the capture is good for 3D reconstruction.

## Known Limitations
- The script uses single-threaded extraction, which is simple but may be slow for very large or high-framerate videos.
- If a video has a variable frame rate (VFR), OpenCV's `CAP_PROP_FPS` may be inaccurate.
- There's no rotation correction (e.g. if a smartphone video was recorded vertically but encoded horizontally with metadata rotation flags).
